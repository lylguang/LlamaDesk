# OmniStudio agent 功能模块优化建议（总表）

- 基线：远端 `origin/main` = 24199d4（v0.1.4），2026-09-21 用 `git ls-remote` 复核未漂移；审查对象是该提交的只读导出，未读本地优化分支。
- 范围：`apps/studio/src/bun/agent*.ts`（约 1.39 万行）、`src/mainview/app/agent/`（约 9700 行）、`src/cli/commands/agent.ts`、相关的 `permissions.ts`、`mcp.ts`、`shutdown.ts`、`db/schema.ts`。
- 依赖边界：循环内核与模型接入来自 `@earendil-works/pi-agent-core` 与 `@earendil-works/pi-ai`（均 0.85.1，`apps/studio/package.json:32-33`），其余全部自研。
- 路径均相对 `apps/studio/`。
- 复核标记：**已复核** = 主 agent 亲自对照基线文件读到；**已复现** = 主 agent 在本机实际跑出；**报告** = 仅来自审查 agent 的报告，未逐条复核，动手前需再看一眼。
- 四份明细（每条含问题机制、改法、风险、验收）：同目录 `agent-core.md`、`agent-context.md`、`agent-tools.md`、`agent-ui.md`。

本地优化分支对该模块几乎没有改动（运行时只碰了 `agent.ts` 2 行、`agent-tools.ts` 约 28 行），下面的建议可以直接在远端基线上做，不牵涉之前评估的合并冲突。

## 第一批：正确性缺陷（小改动、立即可做，约 24 小时）

每条都是独立的小 PR，互不依赖。

1. **`edit_file` 把 `new_str` 里的 `$` 序列当替换模式，静默写坏文件** — 已复核
   - 位置：`src/bun/agent-tools.ts:569`（单次替换走 `String.replace`；`:568` 的全量替换走 split/join，不受影响）；`:559` 空 `old_str` 配 `replace_all` 会在每个字符之间插入内容。
   - 改法：单次替换改成按下标切片拼接（或用函数形式的替换值）；入口拒绝空 `old_str`。
   - 工时 0.5h。验收：新增用例，`new_str` 含 `$&`、`$$`、`$'` 时落盘内容逐字节等于入参。

2. **沙箱对凭据「文件」用 tmpfs 覆盖，bubblewrap 直接启动失败** — 已复现
   - 位置：`src/bun/agent-sandbox.ts:391-394`（对每个存在的凭据路径加 `--tmpfs`），清单里 `:412-414` 的 `.netrc`、`.npmrc`、`.git-credentials` 是文件。
   - 本机复现：对文件路径加 `--tmpfs` 报 `Can't mkdir …: Not a directory`，退出码 1；对目录正常。
   - 后果：用户家目录只要有 `.npmrc`，开沙箱后所有命令都跑不了，还会被识别成「沙箱拦截」并引导用户跳过沙箱（`:729`，报告）。
   - 改法：目录用 tmpfs，文件改用把空文件只读绑定上去覆盖。
   - 工时 2h。验收：家目录放一个 `.npmrc`，沙箱内 `true` 退出码为 0 且读不到原内容。

3. **排队的用户消息被写库两次** — 已复核
   - 位置：入队时 `src/bun/agent.ts:3142-3144` 写一次；出队 `:3185` 调 `runAgentTurn` 没传 `insertUserMessage: false`，`:2465-2474` 再写一次。
   - 改法：出队调用显式关掉插入（同文件 `:3270` 已有同样用法）。
   - 工时 1.5h。验收：运行中排一条消息，结束后 `messages` 表里该内容只有一行。

4. **同一会话没有重入闸门，启动窗口内可并发两轮；启动期按的「停止」被擦掉** — 已复核
   - 位置：运行标记在 `agent.ts:2558` 才置位，之前 `:2444`（等推理服务）与 `:2489`（建会话）都是秒级异步等待；`:3130` 以该标记判断是否直接起新一轮；`:2533` 无条件清掉停止请求。
   - 改法：在函数入口同步置一个「启动中」标记（或按会话的 Promise 锁），第二次发送走排队；停止请求只在真正进入循环后消费，不在启动段清除。
   - 工时 4h。验收：桩一个慢的 `ensureServerReady`，连发两条，断言只有一轮在跑、第二条进队列；启动期按停止后本轮不产生任何工具调用。

5. **「停止」传不到子智能体、web_fetch 与 MCP 调用** — 子智能体部分已复核，其余报告
   - 位置：`agent-tools.ts:1231`（`void signal`）；`agent.ts:1503-1511` 子智能体入参无中止信号；`agent.ts:3219-3222`、`mcp.ts:807-814`（报告）。
   - 改法：`spawnSubagent` 增加 `signal` 参数，子循环监听后调用自己的 abort；fetch 与 MCP 客户端调用透传 signal。
   - 工时 3h。验收：子智能体运行中按停止，之后不再出现新的 `tool_start` 事件。

6. **失败的回合也返回成功，命令行退出码与自动化状态失真** — 已复核
   - 位置：出错分支 `agent.ts:2855-2871` 只往正文追加警告；函数末尾 `:3033-3034` 除钩子拦截外一律 `ok: true`。调用方 `agent-headless.ts:135,151`、`automations.ts:397,411`（报告）。
   - 改法：`outcome.kind === "error"` 时返回 `ok: false` 并带 `error`；无头入口据此设退出码。
   - 工时 2h。验收：桩一个必失败的模型，`omi agent` 退出码非 0，自动化记录为失败。

7. **钩子负载塞进环境变量，超过系统单参数上限后全部钩子按「不拦截」放行** — 已复核（读码），审查 agent 已在本机复现
   - 位置：`src/bun/agent-hooks.ts:141-150`（`OMNI_HOOK_PAYLOAD` 放完整 JSON）；`:160-161` 启动失败返回 `blocked: false`。stdin 已经传了同一份内容（`:158`）。
   - 改法：环境变量只放事件名和一个体积受限的摘要，完整负载只走 stdin；对「拦截型」事件的启动失败改为拦截并提示。
   - 工时 1.5h。验收：200KB 的 prompt 下钩子仍能启动并正常拦截。

8. **glob 的 `**/` 不匹配零层目录，不支持花括号** — 已复核
   - 位置：`agent-tools.ts:342-362`（`**` 直译成 `.*`，其后的 `/` 成为必需；`{}` 被转义）。工具描述里的示例自己匹配不全（`:428`，报告）。
   - 改法：`**/` 译成可选的目录前缀；补花括号展开，或直接换成 Bun 自带的 Glob。
   - 工时 1h。验收：`**/*.ts` 能匹配根目录下的 `a.ts`。

9. **三处界面入口失效** — 第一处已复核，其余报告
   - 运行中的「排队发送」按钮恒禁用：`src/mainview/app/agent/composer.tsx:324-325`（`canSend` 含 `!busy`）与 `:767`（按钮以 `!canSend` 禁用），而 `:770` 的点击处理明明写了排队分支。
   - 用户消息的「回到这条提问」弹窗没有挂载：`message.tsx:517-539`。侧栏「归档」分组不可达：`session-sidebar.tsx:467,784`、`src/bun/agent.ts:1291`。
   - 工时 2.5h。验收：运行中输入文字后按钮可点且消息进入队列面板。

10. **应用退出不收尾 agent，独立进程组的 bash 成孤儿，跑了一半的正文丢失** — 已复核
    - 位置：`src/bun/shutdown.ts` 全文 74 行无任何 agent 调用；bash 以 `detached: true` 启动（`agent-tools.ts:807`）；正文只在回合末落库（`agent.ts:2934-2937`，报告）。
    - 改法：导出 `stopAllAgentRuns()`，登记在途进程组并在 `shutdown.ts` 里整组终止；中止前把已流出的正文落库。
    - 工时 6h。验收：agent 跑 `sleep 600` 时退出应用，进程表里不再有该进程组；重开后能看到半截正文。

## 已经处理好的点（不要重复建议）

- 流式增量在 bun 侧 40ms 合批推送，不是逐 token（`chunk-flusher.ts:13`；`agent.ts:2564-2569`）。
- 事件按步落库；`agent_events` 的 `conversation_id` 单列索引对 `id > ? ORDER BY id` 已够用，不需要复合索引。
- 回合级重试不重放有副作用的工具；崩溃后不自动续跑，只回填并标注「回合被中断」。
- 时间、召回记忆、钩子上下文都在本轮 user 消息里，系统提示保持字节稳定——唯一例外是第 11 条。
- `apply_patch` 先在内存里匹配完再落盘，失败逐笔回滚（`apply-patch.ts:401-484`）。
- bash 超时整组终止、后台进程占住 stdout 不会挂死，均有测试。
- 长列表行级已有 `content-visibility: auto`，暂不需要虚拟列表。

## 建议的落地顺序

1. 第一批 1、2、3、7、8（共约 6.5 小时）：改动最小、后果最重（写坏文件、沙箱不可用、钩子被绕过）。
